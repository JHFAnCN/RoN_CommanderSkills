# RoN 附属 Mod 添加新建筑指南

## 一、源代码（reignofnether）中建筑单位是如何制作的

### 1. 建筑类体系

- **Building**（`building/Building.java`）  
  所有建筑的抽象基类，定义：名称、结构名、图标、成本、阵营、是否首都、是否可修复等，以及抽象方法 `getFaction()`、`getBuildButton(Keybinding)`。

- **ProductionBuilding**（`building/production/ProductionBuilding.java`）  
  继承 `Building`，用于**可生产单位**的建筑（如兵营、城堡），多一个 `productions` 列表（`ProductionItem` + 快捷键）。

- **具体建筑类**  
  例如 `Barracks`、`Watchtower`、`TownCentre` 等，继承 `Building` 或 `ProductionBuilding`，在构造函数里设置：
  - `structureName`：对应 `structures/xxx.nbt` 的文件名（不含扩展名）
  - `cost`：资源消耗（来自 `ResourceCosts` 或 `ResourceCost.Building(...)`）
  - `name`、`portraitBlock`、`icon`、`startingBlockTypes` 等

### 2. 注册流程

1. **注册到建筑注册表**  
   在 `Buildings.java` 里用：
   ```java
   Registry.register(ReignOfNetherRegistries.BUILDING, ResourceLocation.fromNamespaceAndPath(ReignOfNether.MOD_ID, "barracks"), new Barracks());
   ```

2. **加入派系建造列表**  
   在 `FactionRegistries.register()` 里为每个派系调用：
   ```java
   FactionRegistries.register(Faction.VILLAGERS, Buildings.BARRACKS, Keybindings.keyY);
   ```
   这样村民的 `getBuildingButtons()` 会从 `FactionRegistries.VILLAGERS.getBuildingButtons()` 拿到该建筑按钮。

### 3. 结构文件（.nbt）

- 主模组结构路径固定为：**命名空间 `reignofnether`**，路径 `structures/<structureName>.nbt`。
- 在游戏内用**结构方块**保存结构，导出为 .nbt，放到主模组资源的 `data/reignofnether/structures/` 或等价资源目录。
- `Building.getRelativeBlockData(level)` 内部调用 `BuildingBlockData.getBuildingBlocksFromNbt(this.structureName, level)`，只会从 `reignofnether` 命名空间读。

### 4. 放置类型（Placement）

- 普通建筑用默认 `BuildingPlacement`（由 `Building.createBuildingPlacement(...)` 创建）。
- 需要驻军、特殊范围等时用子类，例如 `WatchTowerPlacement`、`ProductionPlacement`；建筑类里重写 `createBuildingPlacement` 返回对应 Placement。

## 二、在 RoN_CommanderSkills 里添加新建筑的步骤

### 方式 A：使用本仓库已有示例（推荐先跑通）

已提供示例建筑 **Commander Tower**（指挥官塔），流程如下。

1. **建筑类**  
   `building/CommanderTower.java`：继承 `Building`，使用主模组已有结构名 `watchtower`，因此不需要自带 .nbt。

2. **注册**  
   - `building/CommanderSkillsBuildings.java`：把 `COMMANDER_TOWER` 注册到 `ReignOfNetherRegistries.BUILDING`。  
   - `RoNCommanderSkillsMod.onCommonSetup` 里：
     - 调用 `CommanderSkillsBuildings.registerBuildings()`（触发静态注册）；
     - 调用 `FactionRegistries.register(Faction.VILLAGERS, CommanderSkillsBuildings.COMMANDER_TOWER, null)`，把该建筑加入村民建造列表（无快捷键传 `null`）。

3. **语言**  
   在 `assets/ron_commanderskills/lang/zh_cn.json` 和 `en_us.json` 中增加：
   - `buildings.villagers.ron_commanderskills.commander_tower`  
   这样 UI 会显示正确名称。

进游戏用村民，在建造栏里应能看到「指挥官塔」，放置后外形与主模组瞭望塔相同（因为共用了 `watchtower` 结构）。

### 方式 B：新增一个完全属于自己的建筑

1. **新建类**  
   例如 `MyBuilding extends Building` 或 `MyProductionBuilding extends ProductionBuilding`，在构造函数里设置：
   - `structureName`：若用主模组已有结构（如 `villager_house`、`watchtower`），直接写该名字；若要用**自己 mod 的结构**，见下方「自定义 NBT 结构」。
   - `cost`：`ResourceCost.Building(食物, 木材, 矿物, 人口)` 或主模组 `ResourceCosts.XXX`。
   - `name`、`portraitBlock`、`icon`、`startingBlockTypes` 等（参考 `Barracks` / `Watchtower`）。

2. **实现必须方法**  
   - `getFaction()`：返回 `Faction.VILLAGERS` / `PIGLINS` / `MONSTERS` / `NONE`。  
   - `getBuildButton(Keybinding hotkey)`：仿照 `CommanderTower.getBuildButton` 或主模组任意建筑，返回 `BuildingPlaceButton`，其中：
     - `isSelected` 用 `BuildingClientEvents.getBuildingToPlace() == 你的建筑单例`；
     - `isEnabled` 一般要求先有城镇中心或作弊研究（参考 `Barracks` / `Watchtower`）。

3. **注册**  
   - 在 `CommanderSkillsBuildings` 里增加：
     ```java
     public static final MyBuilding MY_BUILDING = register(
         ResourceLocation.fromNamespaceAndPath(RoNCommanderSkillsMod.MOD_ID, "my_building"),
         new MyBuilding()
     );
     ```
   - 在 `RoNCommanderSkillsMod.onCommonSetup` 的 `event.enqueueWork` 里增加：
     ```java
     FactionRegistries.register(Faction.VILLAGERS, CommanderSkillsBuildings.MY_BUILDING, null);
     ```
   （若是猪灵/怪物建筑，把 `Faction.VILLAGERS` 换成 `Faction.PIGLINS` / `Faction.MONSTERS`。）

4. **语言**  
   键名格式：`buildings.<阵营小写>.<modid>.<建筑 path>`  
   例如：`buildings.villagers.ron_commanderskills.my_building`。

### 自定义 NBT 结构（建筑外形不沿用主模组）

主模组 `BuildingBlockData.getBuildingNbt` 只从 **reignofnether** 命名空间读 `structures/<name>.nbt`，因此若要用附属自己的结构，有两种做法：

- **做法 1：沿用主模组结构名**  
  把 `structureName` 设成主模组已有的名字（如 `watchtower`、`villager_house`），无需自备 .nbt，最简单；当前 Commander Tower 示例即如此。

- **做法 2：自备 .nbt 并用 Mixin 或重写加载逻辑**  
  - 在你的 mod 资源里放 `assets/ron_commanderskills/structures/xxx.nbt`（或 data 下等价路径）。  
  - 在你的建筑类中重写 `getRelativeBlockData(LevelAccessor level)`：  
    用你自己 mod 的 `ResourceManager` 和命名空间（如 `ron_commanderskills`）读取对应 .nbt，然后调用 `BuildingBlockData.getBuildingBlocksFromNbt(compoundTag)` 得到 `ArrayList<BuildingBlock>` 并返回。  
  - 注意：主模组 `BuildingBlockData.getBuildingNbt(String, ResourceManager)` 是包内方法，若要从不同命名空间读，需要在附属里自己实现一段「按 ResourceLocation 读 NBT」的逻辑（或通过 Mixin 扩展主模组）。

## 三、可生产单位的生产建筑（ProductionBuilding）

若新建筑要像兵营一样**生产单位**：

1. 类继承 `ProductionBuilding` 而不是 `Building`。
2. 在构造函数里添加生产项，例如：
   ```java
   this.productions.add(ProductionItems.VINDICATOR, Keybindings.keyQ);
   this.productions.add(ProductionItems.PILLAGER, Keybindings.keyW);
   ```
   `ProductionItems` 是主模组的；若你要生产主模组没有的单位，需要先在主模组的 `ProductionItem` 体系里注册（或通过主模组/API 扩展）。
3. 重写 `createBuildingPlacement` 返回 `ProductionPlacement`（与主模组 `Barracks` 一致，通常用父类默认即可）。
4. 其他注册、派系、语言与上面「方式 B」相同。

---

## 四、小结

| 步骤           | 说明 |
|----------------|------|
| 建筑类         | 继承 `Building` 或 `ProductionBuilding`，实现 `getFaction()`、`getBuildButton(...)`。 |
| 结构           | 用主模组已有 `structureName` 最简单；要自备外形则需自管 NBT 加载或 Mixin。 |
| 注册到 BUILDING | 在 `CommanderSkillsBuildings` 里 `Registry.register(ReignOfNetherRegistries.BUILDING, id, building)`。 |
| 加入建造列表   | `FactionRegistries.register(Faction.XXX, 你的建筑, keybinding)` 在 `onCommonSetup` 的 enqueueWork 里调用。 |
| 语言           | `buildings.<阵营>.<modid>.<建筑 path>`。 |

当前示例建筑 **Commander Tower** 已按上述流程接好，可直接在游戏中用村民建造测试。
